# 图片规格、预设与参数适配

新创建母版、派生资产、单图、编辑和批量都使用本模块。旧命令保持可读可续接，但缺规格卡的历史轮次标 UNVERIFIED，不自动推断达标。不为升级重做旧角色，不将临时规格写回身份 MD。

项目文档接入在批次总记录保存本次选择、实传参数和文件验证结果，不要求原生规格 JSON 或 spec-adapt；后文“脚本协议”用于完整 Agent。制作档位表达投入/细节意图，不是执行方式；选择卡将工具可直接设置的字段与只能表达意图的字段明确分开，不暗示切换档位一定改变原生参数。

## 给新手的一次规格选择

先读本次明确要求和已有预设，预填已知内容。使用当前环境实际可用的选择题卡片；没有卡片或用户反馈看不见时，立即贴出编号 A/B/C 文字选项，允许自填，不能把工具“已接受”说成用户“已看到”。不依赖某个专用表单插件。

单张：每次新的生图请求都展示并确认制作档位。批量/整包：开始时确认一次共用规格，同时列出逐图例外；不连续问 24 次。若当前消息已明确本次档位和规格，算本次选择，不再重复要求点击。预设只是预填，不能沿用上次确认。续接同批及已获准的同规格返工不重问；改变制作档位/规格须确认受影响项并建立新批/轮次。规格确认不等于授权额外调用或费用。

默认显示这五组，详细项可展开；问题数量按已知信息减去，不让用户学技术名词才可用：

1. 用途：A 日常单人；B 多人同框；C 角色视图板；D 头像；E 竖屏封面；F 自定义。可选择已保存方案。
2. 画幅和比例：A 用途推荐；B 竖幅 2:3 / 3:4 / 4:5 / 9:16；C 横幅 3:2 / 4:3 / 16:9；D 方形 1:1；E 自定宽:高。横竖由比例决定，不设冲突的第二个方向开关。画幅比例不是摄影景别。
3. 本次制作档位（每次选择，不固定默认）：A 试作 preview；B 标准 standard；C 精细 fine。档位只表达投入/细节意图，只有当前工具支持才映射为真实参数；不承诺速度、价格或清晰度。预设可预填，但需本次确认。
4. 像素尺寸：A 当前工具原生尺寸，返回后报告；B 从当前工具真实支持的尺寸中选；C 自定义宽×高。用户说 2K/4K 时先解释指长边还是具体宽高，并落成明确像素；不把写“4K”当获得 4K。
5. 背景与文件：背景 A 当前场景；B 纯色（指定颜色）；C 透明。格式 A 保留原文件；B PNG；C JPEG；D WebP。只显示真实支持的直接输出；JPEG 不支持透明，选择冲突时说明。没有原文件就不能验证格式/透明或完成归档。

详细项按需要展示：全身/半身/特写、头脚和饰物完整性、边缘留白/文字位、参考图优先级、可选身份参数增强、可用且有必要的 seed/步数等。画幅、像素、档位、锐度分别解释：像素多不保证面部细节；真实锐度须看图；输出像素不能证明原生高清。印刷需求才补成品厘米与目标 DPI/PPI，换算像素约为厘米÷2.54×PPI；不以改 DPI 元数据冒充新增细节，也不擅自转色域。

## 预设与数量边界

内置建议见 templates/spec-presets.json：单人 2:3、5–8 人横向 16:9、视图板 3:2、头像 1:1、竖屏 9:16。它们是可改的起点，不强制覆盖用户画幅、角色默认或本次构图。视图板先看格数与辨识度，过密才提议拆分；不得暗增张数。

保存用户常用方案到项目的过程记录/规格预设，不存入 Skill、账号配置或全局家目录。方案不含用户认可原话/当前批 ID；恢复方案仍确认本次制作档位。新名字保存新版本，避免覆盖旧方案。

默认直接完成选定档位的目标图。24 张仍是 24 项首轮任务，不自动变成“24 预览＋24 高清”。自动放大、二次精修、裁剪、扩图、抠图和转格式均未开启。需要时单列操作、受影响图片、是否增加模型调用/费用，获得范围明确的授权，保留原图并另存衍生物。本模块只验证和记录，不偷偷执行这些后处理。

## 提示词和参数分开

提示词写角色、场景、镜头、构图、边缘留白、画风及背景意图。参数计划写实际接口字段：宽高/size、质量档位、输出格式等；未暴露就记未暴露，不编造字段，不把 `--ar`、权重括号或“8K 高清”当通用 API。参考图输入单列编号、角色/场景归属和允许用途。

使用用户指定或当前环境默认图像工具。能力描述来自当前接口/工具说明，记录来源与日期，不能由模型名称推测。工具能力变更时重新核对；能力文件是声明与证据记录，不是自动探测程序。

本版提供声明式适配，不自带 PuLID、ComfyUI、模型 SDK 或收费服务。先检查当前已配置的合适替代工具；新登录、安装、费用不明或超授权再问。已发出失败调用后的切换算额外重试，不能绕过集中返工。

必要规格无法直接设置时，展示“要求是什么／工具能做到或不能保证什么”，让用户选：A 用已配置的合适工具（存在且授权范围内时推荐）；B 保留目标，接受这些指定字段只能作为意图、输出后核验；C 修改指定项；D 暂停。B 不等于目标已满足，也不降低原要求；按输出检查列偏差。不得为了测试支持情况先收费出图。

### 身份注入是可选增强

真实参考图始终必需。identity_control 默认 off；optional 仅在环境支持并能正确绑定时用，否则明确未启用；required 不满足就阻塞相关项。单张多人同时需要所有角色的独立绑定，single 或全局权重不能声称 multi。PuLID 不是必需组件，不要求用户安装。

多角色身份参数需有当前工具支持 multi 的证据、逐人参考编号与真实接口结构。每个绑定检查主人与身份用途，不能拿场景图/风格脸作某人的身份输入。没有独立参数也可用正常多参考图生图，但必须明说未启用独立锁脸，并保持逐人 QA；不承诺 5–8 人一致性。全局参考权重不能伪装成逐人身份注入。

## 脚本协议（完整 Agent）

不要求用户写 JSON/命令；Agent 将真实选择填成 templates/image-specs.json。common 是完整规格；overrides 仅为本批存在的 item ID 到局部规格字段，优先级为逐图 > 本批；confirmation 的 statement 记录本次用户原话，quality_confirmed=true 只能来自本次选择，scope 为 single 或 batch。

单张：`prepare --document MD --specs SELECTION_JSON`。禁止同时用旧 --aspect/--size。新母版沿用 candidate/master；编辑目标仍用 --edit-target，并在适配参数之前加入。

批量：在计划顶层加 `image_specs`，结构同规格卡，scope=batch；共同或逐图原 aspect/size 移入规格卡，别并存。其它 request/style/outfit/cast/scene/shot 保持原协议。每张 prepare 自动绑定同一批确认及本图例外，不增加任务或图像调用。

1. 准备后，读真实工具说明，填写 templates/tool-capabilities.json；没有的能力留未知，不能照抄虚构示例。
2. `spec-adapt --run RUN --capabilities CAPS` 只预检，返回 parameters、uncontrolled、notices，不写冻结计划、不生图。
3. 没有不可控字段，或用户明确接受已列字段后，加 `--commit` 冻结 tool-plan.json。有接受决定时用 `--decision DECISION_JSON`，内容如 `{"accept_uncontrolled":["quality"],"statement":"本次明确接受的原话"}`。这里 quality 仍无法验证，不会伪记原生档位。
4. 实际调用时由 Agent 将 parameters 与 prompt、真实参考图按工具 schema 组合。脚本不自动运行模型。批次 dispatch 在未冻结适配计划时拒绝提交；旧批次兼容但标明旧协议。
5. 回填 generation 的 `applied_parameters` 为真实提交的原生参数对象（无法取得时省略，得到 UNVERIFIED），不能把计划自动抄成实传回执；tool 填实际工具。普通 reference_delivery 证据与实际提示词照常记录。
6. record 自动保存要求／实传／实际输出三栏。检查失败或未验证不丢弃原图，转集中处理；用户明确接受规格偏差/未知才可 `review --status 可用 --approval 原话 --accept-issues`，批次仍用 batch-approve 的同名开关。

保存方案：`spec-preset-save --folder PROJECT --name single-v1 --file SPEC_JSON`；SPEC_JSON 是 common 内容，不是整张确认卡。内置预设只填用途和基本布局，没有默认制作档位。新请求需补全并确认。

### 能力文件结构与约束

parameters 按真实字段列 `type`（string/integer/number/boolean/object/array），可带 enum/min/max；映射仅接受白名单字段。mappings 以 aspect/pixels/quality/format/background 为键，values 的键是规格值（像素为 `宽x高`），值是原生参数对象。例如**仅假设工具真实支持时**：`"pixels":{"values":{"1024x1536":{"width":1024,"height":1536}}}`。质量同理；没有映射不是支持。extra_parameters 也经过类型和范围校验，禁止借它改变输出数量、自动重试、模型路由、凭证或命令。

references.supported 仅在确实支持传图时 true；max_images 为当前上限，未暴露用 null 并记录风险，不能少传必要参考。身份增强使用 identity_binding.mode=single/multi、parameter、evidence；该原生参数还需在 parameters 标记 identity_parameter=true。decision.identity_bindings 为逐角色 `{reference_numbers:[编号],value:本人的参数值}`；decision.identity_native_value 是按真实接口组合的值。程序检查归属/字段类型，但不能证明这个接口真的实现了独立控制或核验任意厂商嵌套语义；Agent 必须对照实际说明核对，无法核对则不启用。不要把通用 owner 表直接塞进不接受它的工具。

## 输出规格与视觉 QA

程序读取真实文件的宽高、比例、编码格式、模式、透明像素，比较明确尺寸和比例；不以文件名/后缀判断格式，不将 RGBA 全不透明或棋盘格视为真透明。PNG 格式并不保证透明。程序比较工具/参数回执，只证明记载是否一致，不证明模型遵循。没有原文件、元数据或参数证据则 UNVERIFIED，不能补写 PASS。

在同一轮视觉检查中覆盖脸和小饰物、手、纹理、背景、裁切及同框逐人身份，与 production/batch 清单合并；疑点才补看相应区域。构图、纯色/场景背景、锐度、原生生成与后期放大来源均不能从像素数推出。分别报告文件/参数校验、视觉检查、用户认可。不把任何一种替代另外两种。

普通聊天也沿用上述选择、分层和三栏核验；不能运行脚本就用文字表，不能读原文件就标无法验证。无需模拟 CLI、哈希或自动批量任务。
